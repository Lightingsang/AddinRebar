# Troubleshooting — symptom → cause → what to do

| Symptom | Cause | Do |
|---|---|---|
| Tool list is empty / server missing in Claude Code | `.mcp.json` has no `hprebar-navis` entry, or the exe path is wrong | user adds the entry (exe `HPNavis/output/HPNavis.Mcp.Server/HPNavis.Mcp.Server.exe`, env `HPNAVIS_MCP_Bridge__HostVersion=2026`); never commit `.mcp.json` |
| Fewer than 24 tools / a seed behaves like an old version | old published exe (seeds are embedded; upgraded on disk only while `_seeds.json` proves the user never edited them) | republish: `dotnet publish HPNavis/HPNavis.Mcp.Server -c Release -r win-x64 -p:PublishSingleFile=true -p:SelfContained=false -o HPNavis/output/HPNavis.Mcp.Server`; the exe is locked while any Claude Code session runs it — rename the running exe (NTFS allows it), publish into the path, restart the sessions |
| Every call: "bridge not connected" / pipe `hpnavis-mcp-2026` missing | Navisworks closed, plugin not loaded, or listener stopped | start Navisworks Manage 2026 with a model; check `%AppData%\Autodesk\Navisworks Manage 2026\Plugins\HPNavis.McpBridge\HPNavis.McpBridge.dll` (folder name = assembly name, required); `dotnet build HPNavis/HPNavis.slnx -c Debug` with Roamer closed deploys it; ribbon **HPNavis ▸ MCP ▸ MCP Bridge** → *Start listener* |
| No bridge log line at all after a Navisworks start | Roamer never loaded the plugin (folder parked/renamed, wrong Navisworks version, plugin blocked) | folder must be exactly `Plugins\HPNavis.McpBridge\`; look for `%LocalAppData%\HPNavis\McpBridge\logs\mcpbridge-<date>.log` with `MCP scripting self-check OK` |
| Bridge log: `FileLoadException` / `System.Text.Json` version mismatch | another plugin's assembly resolver or a foreign System.Text.Json version — `PluginAssemblyResolver` only answers for names shipped in our folder and the same major version | read the log; do not copy DLLs into the other plugin; report |
| `-32001` "Allow AI code execution" | opt-in off (resets on every Navisworks start, never persisted) | user ticks **Allow AI code execution in this Navisworks session**; turning it off also turns heavy off |
| `-32002` "Navisworks is running a command or showing a dialog…" after ~8 s | a modal dialog (Open, Options, Publish…), a file load, a clash run, or a script still running (`Application.Idle` is silent under a native modal; a timer expires the grace) | user closes the dialog / waits; `cancel_execution` stops a cooperative script only |
| `-32003` "No model (.nwd/.nwf/.nwc) is open in Navisworks" | `navis.isClear: true` (start page) | user opens a model |
| `diagnostics[{id: "HEAVY"}]` "… is a heavy operation … 'Allow heavy operations'" | `AppendFile`/`SaveFile`/`Export*`/`TestsRun*`/`doc.Clear()` with the second opt-in off | explain heavy semantics, ask the user to tick the checkbox; never suggest another route |
| "Network (UNC) paths are refused" / "refused path" | heavy literal names `\\server\…`, `HPNavis\McpBridge|McpServer`, or the Navisworks install folder | use a local path the user gave; the policy applies even with heavy on |
| "dryRun cannot undo AppendFile/MergeFile/SaveFile/Export/TestsRunTest" | dryRun + heavy | drop `dryRun` (and get the user's yes) or drop the heavy call |
| `run_tool create_and_run_clash_test` → `HEAVY`; `test_tool` refuses it | heavy seeds cannot be dry-run or tested | run it for real with heavy on, on a saved model |
| "The script declared transaction=\"none\" but modified the document (rolled back: yes)" | a write under `none` | `transaction: "auto"`; `rolled back: no` means the change stayed — tell the user |
| `rolledBack: false` + log "dry run: … no undoable change" | the script changed nothing | not an error |
| `rolledBack: false` + log "dry run: … changed the document without creating an undo entry, so the change persisted" | current viewpoint moved / temporary override / selection change | do not put such calls under `dryRun`; Ctrl+Z will not revert them — say so |
| "Navisworks already has a transaction open (an operation is in progress)" | `doc.IsActiveTransaction` — user mid-operation | wait, retry |
| `GUARD` "… is not allowed in Navisworks scripts" | `Transaction`, `Undo/Redo/Rollback`, `MessageBox`, `Database`/`NavisworksCommand`, COM/Automation namespaces, `SetUserDefined`, base list (`System.IO`, `Task`, reflection, `#r`) | `script-contract.md`; custom properties are COM-only — not scriptable |
| `COMPILE` `CS1061` / `CS0246` / `CS8370` | wrong member, missing namespace, or a .NET 8-only API on .NET 4.8 (`Span`, `Random.Shared`, `Math.Clamp`, `string.Contains(str, comparison)`, positional records) | `inspect_type`; rewrite with 4.8 APIs |
| `timedOut: true` | Descendants walk over a big model, or a heavy call under the 120 s ceiling | `Search` + `PruneBelowMatch` + `Take`; heavy → allow heavy and raise `timeoutSeconds` up to 600 |
| Results cut at 200 items / `truncated: true` | serializer caps (200 per Navis collection, ~64 KB total) | return counts + `Take(n)`; page through `args` |
| `hasClashModule: false` | Navisworks Simulate / Freedom | no clash tool works; say so |
| `find_items_by_property` returns 0 for an obvious property | category/property display names differ (localised UI, `Element` vs `Item`, trailing spaces) | `get_selected_item_properties` on one such item to read the exact names; try `op: "contains"` |
| Second Navisworks: bridge window "Pipe hpnavis-mcp-2026 is already in use — another Navisworks 2026 instance is serving MCP." | one bridge per pipe per version | the first instance keeps serving; close the second or use it without MCP |
| Elevated Roamer, non-elevated server: "bridge not connected" although the pipe exists | pipe ACL is owner-SID only | run both at the same integrity level |
| Ribbon tab **HPNavis** greyed | Navisworks greys every tab on its start page (no model) | open a model; the tab is enabled again |
| `run_tool` refuses a published tool: "quarantined" | ≥ 5 runs with > 40 % failures (argument errors excluded) | fix + `propose_tool {newVersion: true}` → test → publish → CLI approve, or `manage_tool {action: "restore"}` |
| `search_tools` finds nothing for a Vietnamese query | FTS prefix-matches English tokens of the seed descriptions | English keywords (`clash`, `viewpoint`, `set`, `property`) or `search_tools {category: "Selection"}` |
| Harness `run-live-verify.ps1` fails to launch | a Roamer is already running (the harness starts its own) | close Navisworks; the harness kills only what it started; it never touches the foreign `NavisworksMCPPlugin` |

Paths: bridge log `%LocalAppData%\HPNavis\McpBridge\logs\` (shared sink — a second Roamer logs its pipe fault there), settings + audit `%AppData%\HPNavis\McpBridge\` (`settings.json` holds `AutoStartListener` only; `audit\audit-YYYYMMDD.log` one JSON line per run, `[heavy]` tagged), registry `%AppData%\HPNavis\McpServer\` (`registry.db`, `tools-library\<Category>\<name>\`, `_review\`, `_seeds.json`; relocate with `HPNAVIS_MCP_Registry__LibraryPath` / `__DbPath`), plugin `%AppData%\Autodesk\Navisworks Manage 2026\Plugins\HPNavis.McpBridge\`.
