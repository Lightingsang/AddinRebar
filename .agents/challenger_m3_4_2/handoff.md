## 2. Logic Chain

1. **ViewModel Bindings & Two-Way Synchronization**:
   - All input controls in `FoundationSettingView.xaml` bind with `UpdateSourceTrigger=PropertyChanged` to properties generated by `[ObservableProperty]`.
   - When the user edits any input field or toggles `IsTopMatEnabled`, the ViewModel updates synchronously.
   - When `ApplyCommand` runs, `Setting.ToSpec()` maps every field into an immutable `FoundationRebarSpec` snapshot. Because `FoundationRebarSpec` is a C# `sealed record` with `{ get; init; }`, it cannot be mutated after instantiation, guaranteeing thread and state safety.

2. **Pre-commit Validation Integrity**:
   - `FoundationRebarViewModel.ApplyCommand` delegates validation to `FoundationValidationCalculator.Validate(Session.Snapshot, spec)`.
   - The calculator checks:
     - Positive bar spacings and diameters ($s > 0, d > 0$).
     - Non-negative concrete covers ($c \ge 0$).
     - Boundary clearance ($L > 2c_{side}$ and $W > 2c_{side}$).
     - Slab thickness clearance ($H \ge c_{top} + c_{bot} + \sum d_{active}$).
     - Excessive bar count ($\le 1002$ bars per layer).
   - If any check fails, `HasValidationError` becomes `true`, the error banner displays the message, and execution aborts before modifying `Session.Spec` or closing the modal dialog. This prevents invalid parameters from ever reaching the Revit transaction or creation service.

3. **Atomic Transaction Group Safety**:
   - In `FoundationRebarOrchestrator`, `group.Start()` is wrapped in a `using var group` pattern.
   - If the user cancels the dialog or closes the window (`dialogResult != true || viewModel.DialogResult != true`), `group.RollBack()` is immediately called, ensuring no partial edits persist.
   - Rebar creation is encapsulated within an inner `Transaction`, isolating document mutations.
   - On successful execution, `group.Assimilate()` combines the operations into a single named undo action ("Foundation Rebar").
   - On any failure or unexpected exception, the inner transaction scope disposes (rolling back uncommitted mutations), and the outer catch block invokes `group.RollBack()`, restoring the Revit document to its pristine pre-command state.
