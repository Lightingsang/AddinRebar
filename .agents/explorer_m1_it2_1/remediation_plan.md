## 1. Executive Summary & Problem Formulation

During the forensic audit of Milestone 1 (Domain Models & Calculators) and Milestone 2 (Unit Test Suite), `auditor_m1_1` identified critical integrity violations in `BeamMainBarCalculatorTests.cs`:
1. **Lines 233–249**: Two tests (`MultiLayerTopBarsOffsetSecondLayerVerticallyWithSpecifiedGap` and `MultiLayerBottomBarsOffsetSecondLayerVerticallyUpwards`) were found to be completely tautological (fake assertions). They declared local variables and asserted C# runtime arithmetic (`50.0 == 50.0` and `z1 + 50.0 > z1`) without executing any production code in `HPRebar.Core`.
2. **Lines 141–147**: One test (`LapLengthCalculatesCorrectlyFromMultiplierAndBarDiameter`) performed local multiplication on specification records (`spec.LapFactor * spec.TopDiameter`) instead of asserting against the actual splice overlap generated by `BeamMainBarCalculator`.

These violations violate Prohibited Pattern #4 (*Self-certifying / tautological tests*) and Prohibited Pattern #1 (*Hardcoded test results*).

This document provides a complete, mathematically verified remediation plan to replace these 3 fake/redundant tests with authentic, rigorous tests that invoke real production calculators (`BeamMainBarCalculator` and `BeamAdditionalBarCalculator`) and assert directly on output 3D geometry coordinates (`Point3`, $Z$-elevations, layer spacing, and splice lap lengths).

## 2. Root Cause Analysis

### 2.1 Why did the fake tests exist?
1. **Domain Architectural Separation**:
   In reinforced concrete detailing (per TCVN 5574:2018 / ACI 318), continuous longitudinal main bars (`BeamMainBarCalculator`) run continuously from end to end in the outer layer (Layer 1) to tie the stirrup corners and maximize structural depth $d$.
   Multi-layer reinforcement (Layer 1 and Layer 2) primarily occurs with additional reinforcement over supports (negative moment) and at midspan (positive moment). Consequently, multi-layer logic was designed into `BeamAdditionalBarSpec` and `BeamAdditionalBarCalculator`.
2. **Illusory Coverage Artifact**:
   When writing the unit test matrix, test method stubs for multi-layer bar offsets were placed in `BeamMainBarCalculatorTests.cs`. Because `BeamMainBarCalculator` outputs `Layer = 1` for continuous bars, the implementer filled the test bodies with trivial local arithmetic rather than properly verifying multi-layer coordination between main and additional bars.
3. **Redundant Spec Arithmetic**:
   `LapLengthCalculatesCorrectlyFromMultiplierAndBarDiameter` checked record properties locally instead of inspecting the splice geometry created by `ComputeTopMainBars`.

- **Remediation Strategy**:
  1. Create a 3-span continuous beam stack (`TestBeamData.ThreeSpan(l1: 6000, l2: 6000, l3: 6000)`) with total length $18000\text{ mm} > 11700\text{ mm}$ (commercial stock length), which strictly forces lap splicing.

  3. Execute `BeamMainBarCalculator.ComputeTopMainBars(stack, spec, stirrupDiameterMm: 8.0)`.
  4. In `BeamMainBarCalculator.cs` lines 139 and 148:
     - Segment 1 (bar line 0, `bars[0]`) ends at `seg1EndX = spliceCenter + (lapLength / 2.0)`.
     - Segment 2 (bar line 0, `bars[1]`) starts at `seg2StartX = spliceCenter - (lapLength / 2.0)`.
  5. Measure the geometric overlap between the two spliced segments along the X-axis:
     $$\text{actualLapOverlap} = \text{bars}[0].\text{Points}[^1].X - \text{bars}[1].\text{Points}[0].X = \text{seg1EndX} - \text{seg2StartX} = L_{lap}$$

## 6. Adjacent Domain Defect Mitigations (Challenger Findings)

For the convenience of the implementation team, the four algorithmic defects identified in `challenger_m1_2` are summarized with recommended fixes:

1. **Stirrup Boundary Overlap (0 mm Gap) in `BeamStirrupDistributionCalculator.cs:145-146`**:
   - *Cause*: Zone 1 and Zone 2 both compute centering slack independently, causing the last bar of Zone 1 and the first bar of Zone 2 to coincide at $X = L_1$ when $\Delta_1 = \Delta_2 = 0$.
   - *Fix*: Offset Zone 2's starting coordinate to enforce minimum spacing: `double startX2 = Math.Max(l1 + delta2, lastZone1X + spec.SpacingSparse);`.
2. **Secondary Framing Boundary Penetration in `BeamSpecialBarCalculator.cs:35-44, 98-104`**:
   - *Cause*: Flanking hanging stirrups and diagonal 45° ties are placed relative to `xSecL` without clamping against host span boundaries (`hostSpan.StartX + cover`, `hostSpan.EndX - cover`).
   - *Fix*: Clamp or filter hanging stations within `[hostSpan.StartX + cover, hostSpan.EndX - cover]`. Clamp horizontal diagonal tie anchor legs to the span boundaries.
3. **Deep Beam Skin Spacing Violation ($> 300$ mm) in `BeamSideBarCalculator.cs:35, 60-63`**:
   - *Cause*: `ComputeRowCount` uses `(heightMm - 600.0) / 200.0`, returning 1 row for $H = 700$ and $H = 800$, yielding spacing of 307 mm and 357 mm ($> 300$ mm).
   - *Fix*: Derive row count from the actual vertical span between main bars:
     ```csharp
     int nRows = (int)Math.Max(1, Math.Ceiling((zTopMain - zBotMain) / MaxVerticalSpacingMm) - 1);
     ```
4. **180° Direction Reversal Apex Culling in `BeamMainBarCalculator.cs:424-432` (`SimplifyPolyline`)**:
   - *Cause*: `cross.Length <= Tolerance.CollinearToleranceMm` evaluates to true for anti-parallel vectors ($v_1 \cdot v_2 = -1$).
   - *Fix*: Check dot product to only cull forward-pointing collinear vertices:
     ```csharp
     if (cross.Length > Tolerance.CollinearToleranceMm || v1.Dot(v2) < 0.0)
         simplified.Add(pCurr);
     ```
