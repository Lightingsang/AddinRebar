## 1. Executive Summary

- **Overall Risk Assessment**: **MEDIUM**
- **Core Implementation**: The core logic in `HPBim.Client.Recovery.ReconcileService` and `HPBim.Client.Connection.IntentJournalRecord` successfully implements the persist-before-terminal sequence and exact keyset bijection validation when `LedgerFilePath` and `SourceKeys` are provided.
- **Empirical Test Verification**: 
  - Worker's 6 integration tests in `ReconcilePersistBeforeTerminalTests.cs`: **6/6 PASS**.
  - Challenger's 7 rigorous stress & boundary tests in `EmpiricalChallenger1PersistTests.cs`: **7/7 PASS**.
  - Full HPBim test suite (`dotnet test HPBim.slnx`): **1004/1004 PASS** across Core, Client, and E2E suites with 0 regressions.
- **Adversarial Vulnerabilities & Gaps Found**:
  1. **[HIGH] CLI Integration Bypass**: `HPBim.Cli.Commands.CoordinationCommand.cs` (line 179) instantiates `ReconcileService` without passing `ledgerPath`, causing `LedgerFilePath` to remain `null`. As an empirical test proved, `ReconcileService` skips disk persistence when `LedgerFilePath` is null and commits the journal *before* `CoordinationCommand` writes the ledger. If a crash or disk failure occurs between journal commit and CLI save, the persist-before-terminal guarantee is broken in production CLI usage.
  2. **[HIGH] Pre-Dispatch Intent Keyset Population Gap**: `HPBim.Client.Pipeline.BimPipelineEngine.IntentJournal.cs` (line 107) records pre-dispatch intents with `ItemCount = plan.Items.Count`, but fails to populate `SourceKeys = plan.Items.Select(...)`. Consequently, all intents generated by actual pipeline runs default to empty `SourceKeys`, causing `ReconcileService.ValidateKeysetCoverage` to fall back to scalar count comparison rather than exact keyset coverage.

## 2. Empirical Verification Findings

### A. Persist-Before-Terminal Invariant
- **Hypothesis**: If ledger save throws an exception (disk full, lock contention, permissions, unwriteable directory), the journal must NEVER transition to `Committed` and must retain `OutcomeUnknown`.
- **Empirical Test**: `PersistBeforeTerminal_WhenSaveThrowsUnauthorized_JournalNeverCommitted`
  - Reconcile attempted with an unwritable directory path.
  - Result: `ReconcileStatus.StillUnknown`, error captured, `journal.GetIntentAsync(opId).Status == IntentStatus.OutcomeUnknown`, `IsTerminal == false`.
  - **Verdict**: **VERIFIED / PASS**.

- **Hypothesis**: The physical file `bim_coordination_ledger.json` must be flushed to disk strictly BEFORE `_journal.UpdateStatusAsync(..., IntentStatus.Committed)` executes.
- **Empirical Test**: `KeysetCoverage_TemporalOrderStrictlyVerifiedBySpy`
  - Spy intercepted `UpdateStatusAsync`: checked if the ledger file existed and contained all 2 deserializable mappings at the exact millisecond of commit call.
  - Result: Verified true.
  - **Verdict**: **VERIFIED / PASS**.

### B. Exact Keyset Coverage & Bijective Mapping
- **Hypothesis**: If a receipt misses even 1 key out of N (e.g. 1 out of 100), reconcile must reject and preserve `OutcomeUnknown`.
- **Empirical Test**: `KeysetCoverage_When1OutOf100KeysMissing_OutcomeStrictlyUnknown`
  - Intent recorded with 100 elements (`Doc#Column:C1..C100`).
  - Receipt provided 99 elements (missing `C100`).
  - Result: `ReconcileStatus.StillUnknown`, diagnostic message `"missing=1, foreign=0"`, ledger file not created, journal status `OutcomeUnknown`.
  - **Verdict**: **VERIFIED / PASS**.

- **Hypothesis**: If a receipt provides the exact count N, but 1 key is foreign (e.g. `ForeignX` replacing `C100`), reconcile must reject.
- **Empirical Test**: `KeysetCoverage_When1OutOf100KeysForeign_OutcomeStrictlyUnknown`
  - Intent recorded with 100 elements.
  - Receipt provided 100 elements (99 matching, 1 foreign).
  - Result: `ReconcileStatus.StillUnknown`, message `"missing=1, foreign=1"`, ledger file not created, journal status `OutcomeUnknown`.
  - **Verdict**: **VERIFIED / PASS**.

### C. Receipt Payload Integrity
- **Hypothesis**: If a receipt contains malformed or unparseable composite keys or empty uniqueIds, reconcile must preserve `OutcomeUnknown` without corrupting ledger mappings.
- **Empirical Tests**:
  - `InvalidPayload_WhenKeyIsUnparseable_PreservesOutcomeUnknown_NoLedgerMutation`: Key with malformed structure or unparseable category rejected (`StillUnknown`), 0 ledger mutations.
  - `InvalidPayload_WhenUniqueIdIsWhitespace_PreservesOutcomeUnknown_NoLedgerMutation`: Whitespace uniqueId rejected with message `"empty uniqueId"`, 0 ledger mutations.
  - **Verdict**: **VERIFIED / PASS**.

## 3. Vulnerability & Challenge Analysis

### [High] Challenge 1: `CoordinationCommand.cs` Omits `ledgerPath` in `ReconcileService` Constructor
- **File**: `HPBim/src/HPBim.Cli/Commands/CoordinationCommand.cs:179`
- **Code**:
  ```csharp
  var service = _reconcileService ?? new ReconcileService(journalToUse, pipeClient, _ledgerService);
  return await RunReconciliationLoopAsync(service, opStr, ledgerPath, ct).ConfigureAwait(false);
  ```
- **Vulnerability**:
  Worker added the overloaded constructor `ReconcileService(journal, pipeClient, ledgerService, receiptReader, ledgerFilePath)` and property `LedgerFilePath`. However, Worker did not update `CoordinationCommand.cs` to pass `ledgerPath`.
  When `service.ReconcileIntentAsync` executes:
  `service.LedgerFilePath` is `null`. In `PersistLedgerBeforeCommitAsync`:
  ```csharp
  if (string.IsNullOrEmpty(LedgerFilePath)) return null;
  ```
  It returns `null` (no error). The journal is marked `Committed` on disk BEFORE the ledger is saved to disk!
  Only after reconcile completes does `CoordinationCommand.ProcessReconcileResults` call `_ledgerService.SaveToFile(ledgerPath)`.
- **Attack / Failure Scenario**:
  User runs `hpbim reconcile`. A receipt is recovered. `ReconcileService` commits the journal. Before `CoordinationCommand` saves the ledger file, disk write fails or process is killed (SIGKILL / power loss).
  On restart, the journal is marked `Committed`, but `bim_coordination_ledger.json` never received the mappings. Rerunning `hpbim generate` will duplicate elements because ledger mappings were lost.
- **Mitigation**:
  Update `CoordinationCommand.cs:179` to:
  ```csharp
  var service = _reconcileService ?? new ReconcileService(journalToUse, pipeClient, _ledgerService, ledgerFilePath: ledgerPath);
  ```

---

### [High] Challenge 2: `BimPipelineEngine` Does Not Populate `SourceKeys` on Intent Creation
- **File**: `HPBim/src/HPBim.Client/Pipeline/BimPipelineEngine.IntentJournal.cs:107-116`
- **Code**:
  ```csharp
  var record = new IntentJournalRecord
  {
      OperationId = plan.Options.OperationId,
      PlanHash = plan.PlanHash,
      TimestampUtc = DateTime.UtcNow,
      Status = IntentStatus.InFlight,
      ItemCount = plan.Items.Count,
      TargetDoc = plan.TargetDoc,
      ErrorReason = null
  };
  ```
- **Vulnerability**:
  `record.SourceKeys` is left as default `Array.Empty<string>()`.
  When `ReconcileService.ValidateKeysetCoverage` executes during real recovery:
  ```csharp
  if (intent.SourceKeys != null && intent.SourceKeys.Count > 0)
  ```
  evaluates to `false`. Reconcile falls back to:
  ```csharp
  else if (intent.ItemCount != elementMap.Count)
  ```
  Exact keyset coverage (R2-B) is never applied to real pipeline intents. A receipt returning foreign keys with the same count will be mistakenly accepted.
- **Mitigation**:
  In `BimPipelineEngine.IntentJournal.cs`:
  ```csharp
  SourceKeys = plan.Items.Select(item => item.SourceKey.ToString()).ToArray(),
  ```

## 5. Conclusion & Recommendation

The core mechanics of Milestone 2 (M2) in `ReconcileService` and `IntentJournalRecord` are solidly implemented and verified under rigorous adversarial conditions.
However, because of the integration disconnects in `CoordinationCommand.cs` (not passing `ledgerPath`) and `BimPipelineEngine.IntentJournal.cs` (not populating `SourceKeys`), the persist-before-terminal and exact keyset coverage guarantees are currently vulnerable when invoked through the CLI and real pipeline dispatch.

**Verdict Recommendation**: **REQUEST_CHANGES** (or conditional APPROVE with mandatory follow-up fixes in Milestone 4 where `BimPipelineEngine` and CLI integration are scheduled).
