## 2. Logic Chain

1. **Host-Independent Decoupling**:
   `HPBim.Client` executes all Revit operations through dynamic C# scripts sent over the `\\.\pipe\hprebar-mcp-r2026` Named Pipe to the in-process `HPRebar.McpBridge`. This ensures that `HPBim.Client` does not link against Revit API assemblies, allowing it to target both `net8.0` and `net10.0` and run cross-platform/out-of-process without assembly locking.
2. **Roslyn Script Correctness**:
   Scripts generated by Stages 1 through 8 and `CompositeBimGenerator` implement actual Revit API creation methods (`Level.Create`, `Grid.Create`, `FamilyInstance` placement for Columns, Beams, Doors, Windows, Plumbing fixtures, `Floor.Create`, `Wall.Create`, `doc.Create.NewRoom`, and `Rebar.CreateFromCurves`). All scripts pass Roslyn AST parsing without errors.
3. **Atomic Dry-Run Rollback**:
   Executing individual stages sequentially in dry-run mode would cause earlier stages (such as Level creation) to roll back before later stages execute, causing missing dependency errors. `CompositeBimGenerator` solves this by packaging all 8 stages into a single atomic script inside one `TransactionGroup`, ensuring that dependent elements exist in memory during execution before a clean rollback.
4. **Clean Code Rule Conformance**:
   Class bodies are <= 290 lines, all catch blocks are documented with justification comments, there is zero dead code, and the single 58-line method `CompareCounts` is a cohesive object initializer mapping 11 categories without complex branching or nested loops.
