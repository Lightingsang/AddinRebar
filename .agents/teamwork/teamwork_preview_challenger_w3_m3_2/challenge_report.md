## 1. Challenge Summary

Worker M3 implemented the decoupling of persistent document identity (`Title`, `PathName`, `CentralGuid`) from the dynamic revision state (`VersionGuid`, `NumberOfSaves`), resolved fail-open vulnerabilities in `ReconcileService`, and structured the domain snapshot in `DocSnapshot.cs`.

Challenger 2 subjected the changes to rigorous empirical adversarial testing across 4 dimensions:
1. **Dynamic VersionGuid Mutation Resilience**: Advancing `VersionGuid` post-commit across single and multiple element mutations.
2. **Fail-Open Boundary Conditions**: Empty, whitespace, null, all-zero, and malformed inputs in receipt fields (`TargetDocPath`, `TargetCentralGuid`).
3. **Path Slash Formats (`\` vs `/`)**: Strict ordinal case-insensitive string equality vs path canonicalization.
4. **`DocSnapshot` API Robustness**: Cross-checking `MatchesStaticIdentity` and argument mapping in `ReconcileService.DocSnapshot.cs`.
5. **Zero Regression Verification**: Full test suite runs across `HPBim` (1,044 tests), `McpShared` (1,030 tests), and `HPRebar` (1,800 tests).

## 2. Adversarial Challenges & Findings

### Challenge 1 (Low / Robust): Dynamic VersionGuid Mutation Decoupling
- **Assumption Challenged**: Eliminating `VersionGuid` equality from `MatchTargetDocSnapshot` allows successful receipt recovery after Revit commits transaction-advancing element mutations, while still verifying 3-factor integrity (`OperationId`, `PlanHash`, static doc identity).
- **Attack Scenario**: Pre-flight snapshot records $V_1$ (`11111111-1111-1111-1111-111111111111`). Receipt records $V_2$ (`22222222-2222-2222-2222-222222222222`). Intent has $N=2$ elements mutated.
- **Empirical Result**: PASS. `ReconcileService` successfully verifies all 3 factors, marks the intent `Committed`, populates ledger mappings, and never rejects legitimate transactions.
- **Blast Radius**: None. Pre-flight concurrency guard (`BimPlanRunnerScriptTemplate.cs`) remains separate to prevent concurrent dispatch, while post-commit recovery succeeds.

### Challenge 2 (Low / Robust): Elimination of Fail-Open Vulnerabilities
- **Assumption Challenged**: Missing or invalid fields in receipt cannot silently bypass static identity constraints when intent specifies them.
- **Attack Scenario**:
  - Intent specifies `PathName = @"C:\Bim\Model.rvt"`, receipt provides `""`, `"   "`, or `null`.
  - Intent specifies `CentralGuid = Guid.NewGuid()`, receipt provides `""`, `"   "`, `"00000000-0000-0000-0000-000000000000"`, or `"malformed-guid"`.
- **Empirical Result**: PASS. In all cases, `MatchTargetDocSnapshot` returned `false`, preserving `IntentStatus.OutcomeUnknown` and leaving ledger unmutated. No fail-open occurs.
- **Mitigation Status**: Fully verified in `EmpiricalChallenger2M3DocumentIdentityTests.cs`.

### Challenge 3 (Low / Observation): Path Slash Formats (`\` vs `/`)
- **Assumption Challenged**: If an intent specifies `PathName = @"C:\Bim\Folder\Model.rvt"` and receipt specifies `"C:/Bim/Folder/Model.rvt"`, does reconciliation match or reject?
- **Attack Scenario**: Dispatch with mixed forward/backward slashes.
- **Empirical Result**: REJECTED (`OutcomeUnknown`). `string.Equals(..., StringComparison.OrdinalIgnoreCase)` compares raw characters and does not normalize slashes.
- **Assessment**: In native Revit API execution, `doc.PathName` on Windows always produces backslashes (`\`), so receipts generated by the bridge will naturally match Windows file paths. The strict check fails closed (safe) rather than fail-open.
- **Recommendation**: In a future non-breaking enhancement, consider `Path.GetFullPath` or normalizing slashes (`.Replace('/', '\\')`) if cross-platform client callers submit POSIX slash paths.

### Challenge 4 (Medium / Non-Blocking Finding): `ReconcileService.DocSnapshot.cs` Line 92 Argument Mapping
- **Assumption Challenged**: `ReconcileService.MatchTargetDocSnapshot(DocSnapshot, CoordinationReceiptRecord)` correctly delegates to `DocSnapshot.MatchesStaticIdentity`.
- **Observation**:
  In `ReconcileService.DocSnapshot.cs` lines 88-93:
  ```csharp
  return targetDoc.MatchesStaticIdentity(
      actualTitle,
      receipt.TargetDocPath,
      receipt.TargetCentralGuid,
      receipt.TargetCentralGuid);
  ```
  `MatchesStaticIdentity` has signature:
  `MatchesStaticIdentity(string actualTitle, string? actualPath, string? actualCentralGuid = null, string? actualProjectGuid = null)`.
  Line 92 passes `receipt.TargetCentralGuid` as both parameter 3 (`actualCentralGuid`) and parameter 4 (`actualProjectGuid`).
- **Attack Scenario**: Caller supplies a `DocSnapshot` with `CentralGuid = G1` and `ProjectGuid = G2` ($G_1 \neq G_2$). Receipt supplies `TargetCentralGuid = G1`.
- **Empirical Result**: `MatchesStaticIdentity` evaluates `ProjectGuid.Value != projGuid` where `projGuid` received `receipt.TargetCentralGuid` ($G_1$), causing mismatch and returning `false`.
- **Blast Radius**: Isolated. In the production pipeline, `ReconcileService.MatchTargetDocId` uses `intent.TargetDoc` of type `DocumentIdentitySnapshot`, which calls the overload on lines 34-75 (which only evaluates `Title`, `PathName`, `CentralGuid`). The `DocSnapshot` overload is a secondary helper and not in the critical path.
- **Recommendation**: Change line 92 to pass `null` for `actualProjectGuid` (or add `TargetProjectGuid` to `CoordinationReceiptRecord` if ProjectGuid is persisted in Revit Extensible Storage).
