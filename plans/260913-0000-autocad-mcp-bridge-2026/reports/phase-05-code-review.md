## Design verdict — stability window

**Argument errors excluded (`error NOT LIKE 'Argument%Exception:%'`) — accepted, with two caveats to document.**
The phase-04 review (#13) asked for exactly this decision and the live run proved the failure mode (a validating seed quarantined by wrong calls). String-prefix matching on `"{TypeName}: {message}"` is safe on both bridges (verified above) and cheap. Trade-off the code comment over-claims ("reports a wrong call, not a broken tool"): `Autodesk.Revit.Exceptions.ArgumentException` / `ArgumentNullException` / `ArgumentsInconsistentException` share the short name with `System.*`, so a tool whose **own code** hands the Revit API a degenerate curve, a wrong `ElementId` or a bad parameter is now invisible to auto-quarantine; on AutoCAD the `AcadException` branch keeps `eKeyNotFound`/`eInvalidInput` visible, but `System.ArgumentException` thrown by AutoCAD.NET wrappers (e.g. `Color.FromColorIndex` range, `Handle` parsing) is hidden too. That is the cheaper failure — each run still returns `isError` to the AI, only the `tools/list` hygiene net is weaker — so it is acceptable, but (a) write the trade-off into the `StabilityRunFilter` comment and Revit ADR-06, and (b) the clean long-term fix is a structured `errorKind` on `ExecuteResult` (additive Contracts change) set by the runner from the exception's **namespace** (`System` → caller, `Autodesk.*` → API), which removes string matching entirely.

**Window restarts at the last `approved`/`published`/`restore`/`proposed_version` — accepted.** Correct SQL in both queries, same ms clock, `>=` on the right side, history queries untouched. Gaps: the tool.json hand-edit and `import` paths write no event (#1 — the one real hole), `restore` is effectively redundant (#4). `StabilityScorer` is untouched; the semantic change is that `runs`/`stability` in `search_tools`, `get_tool`, `_review/*.md` and `registry list` now mean "counted runs since the last approval, excluding argument refusals" — a freshly re-approved tool ranks at `0.5 × textScore` until it accumulates runs, which is the intended "trust must be re-earned" behaviour and should be one line in the docs (#15).
