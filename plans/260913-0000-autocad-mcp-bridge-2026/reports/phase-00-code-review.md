## Per-criterion verdicts

- **(a) zero behaviour change for Revit MCP** — PASS with reservations. tools/list byte-identical (34); pipe `hprebar-mcp-r2026`, registry root `%AppData%\HPRebar\McpServer`, settings `%AppData%\HPRebar\McpBridge`, `revit.*` methods all preserved (verified by reading + `HostNeutralityTests`). Contracts additive only: `PipeNaming.For(string,int)`, suffix constants, `ContextResult.Host/HostVersion/Autocad`, `AutocadInfo`, `HostScriptContracts`; no field renamed/removed; old bridge's `revit.progress`/`revit.status` still matched by suffix. Deviations: `serverInfo.name` (F3) and three error-message strings (F4). Live check with the deployed bridge is claimed by the plan but not evidenced in `reports/`.
- **(b) touchpoints** — PASS. `HPRebar.McpBridge` (Application, Command, view code-behind, XAML `xmlns:vm` with `assembly=`), server exe, both test projects and `ResolveConfigurationsModule` all build; 171 tests pass.
- **(c) no cross-wiring** — PASS. No `Autodesk.*`/Nice3point reference in McpShared (grep + `Shared_assemblies_reference_no_host_api`); McpShared csproj/slnx reference only siblings; `HPRebar/` references `..\..\McpShared\` by relative `ProjectReference`; `HPAutoCad.slnx` references `../McpShared/` only. Soft couplings only: `InternalsVisibleTo` names and the linked test file (F13).
- **(d) public contracts / defaults** — PARTIAL FAIL. Optional parameters (`RequestDispatcher` hostName="Revit", `TypeInspector` hostName="Revit", `RevitBridgeClient`/`RegistryStartup` profile=`HostProfile.Revit`, `McpBridgeStatusViewModel` clipboard, `McpBridgeHost` 3-arg ctor) preserve old behaviour for Revit. `BridgeOptions.RevitVersion` alias binds correctly (probe: `Bridge:RevitVersion=2025` → `HostVersion=2025`, pipe `hprebar-mcp-r2025`). Explicit `Registry:LibraryPath` still wins (probe case 3). **But** the computed defaults are pinned by the binder before `PostConfigure` runs whenever the section is non-empty (F2) — the `ProductFolder`/`HostId` mechanism does not work for any host whose defaults differ from Revit.
- **(e) thread-safety of the view model** — FAIL at HEAD, PARTIAL in working tree (F1). `SynchronizationContext.Current` is not guaranteed on the Revit UI thread in a sync `ExternalCommand`; HEAD's fallback posts synchronously on the pipe thread and can wedge the executor (`_busy` never reset). Working tree injects the WPF dispatcher for Revit (correct) but Core keeps a silent synchronous fallback for future hosts.
- **(f) notification naming** — PASS. `ProgressMethodFor("revit.execute")` → `revit.progress`, bare method → `revit.progress`; client matches by suffix (`IsProgress/IsStatus/IsLog`); `McpBridgeHost._statusMethod` = `methodPrefix + "status"` = `revit.status` for the Revit ctor. Only gap: prefix without trailing dot is not validated (F10).
- **(g) host field on existing tools** — PASS. `ToolManager.LoadAllAsync` does `record.Host ??= profile.HostId` before comparing, so the 22 host-less files load; the loop never writes files (only `_db.UpsertTool`), so `host` reaches disk only through `ToolManager.Save` → `ToolLibraryStore.Write` (also adds `"hostVersions": []`). `RegistryJson` skips nulls. No test covers it (F11).
- **(h) ScriptGuard messages** — PASS. `GuardProfile.Revit` = `new GuardProfile("Revit")` with empty extras; every interpolation `{_host}` reproduces the previous literals exactly (`"… in Revit scripts."`, `"… on Revit's API thread."`); moved `ScriptGuardTests` pass unchanged. `AnalyzerProfile.Revit` reproduces the `Transaction|TransactionGroup|SubTransaction` check; new method-name check is a no-op with an empty set.
- **(i) SeedInstaller default assembly** — PASS. Only production caller is `RegistryStartup.cs:45`, which passes `_profile.HostAssembly`; test callers pass `RegistryFixture.RevitSeeds`. Risk is the silent-zero default via `HostProfile.Revit` (F5).
- **(j) build pipeline** — PASS. `HPRebar/build` compiles with 0 warnings; Sourcy scan root is `HPRebar/` so `Solutions.HPRebar` is unambiguous; repo contains only `.slnx` files, so dropping the `.sln` fallback loses nothing. Unused `context` parameter (F12).
