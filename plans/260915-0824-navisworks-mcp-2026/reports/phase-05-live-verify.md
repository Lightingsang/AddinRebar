## Harness design notes (differences from the AutoCAD harness worth keeping)

- One Python file, phases selected by `--phase`; the PowerShell wrapper owns everything that needs the desktop (Roamer start, UIA opt-ins on our window only, Ctrl+O modal, Win32 dialog close, second Roamer, plugin folder park/restore) and calls Python once per phase on one registry root. `--out` writes `summary-<phase>.json`; `types.json` carries the two most common `Item.Type` values from `main` to `heavy` so the clash pair does not depend on gatehouse's naming.
- The registry root lives under the run's output folder (`-Tag`) and is recreated per run, so every run starts from the 12 seeds; the CLI approve uses the same env vars.
- The friendly pipe-in-use text is a `Faulted` event → status window (`StatusDetail`); the shared log carries only the `IOException`. The harness reads both.
- `count_items_by_source_file` (the MISS → tool) walks `RootItems.SelectMany(DescendantsAndSelf).Take(maxItems)` and reads `Item.Source File` via `FindPropertyByDisplayName` + `IsDisplayString` dispatch — same contract as the seeds. The proposal's `warnings` list the two remaining hard-coded strings ("Item", "Source File") as candidate parameters, as designed.
- Nothing in the harness touches the foreign `NavisworksMCPPlugin` folder; isolation parks **our** folder only. The plan's optional "disable the foreign plugin for a clean run" was not done (it needs the user's go-ahead).
