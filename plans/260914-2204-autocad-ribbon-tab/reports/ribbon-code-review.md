## Lifecycle / threading verdict
Correct. Three creation paths, all main-thread, all through one `FindTab`-guarded `EnsureCreated`; both event handlers unsubscribe before creating, so re-entrancy cannot duplicate; the presenter is disposed before every rebuild and the bridge-side unsubscribe uses the same closure instance. Dispatcher is the right one (RibbonControl is a WPF Control) and the fallback is safe because RibbonItem is not a DependencyObject (verified in AdWindows 25.1.0 metadata, not assumed). Loose ends are state hygiene (#5) and two rebuild triggers the design does not cover (#13, accepted in the plan for CUILOAD).

## Parity verdict
Clean. `McpShared/`, `HPRebar/`, `HPAutoCad.Mcp.Server(.Tests)` untouched (stat empty); bundle carries no Autodesk DLL; the four `HPMCP*` commands take the same `BridgeActions.Run` path with one deliberate change — no-document routing now alerts for `status` and for failures (was silent) — matching phase-01 §Requirements; the five new dictionary entries are additive and an old bridge degrades to "Không đọc được trạng thái bridge" + a `KeyNotFoundException` alert rather than a crash. Claude Code's stdio flow is unaffected by construction (server not in the diff); 22/22 per the live report, tester to confirm.

## Standards verdict
Pass. File-scoped namespaces match folders, `sealed` where instantiable, nullable annotations right, longest file 183 lines, Vietnamese labels/tooltips read naturally and name the equivalent command, no machine paths or secrets, BCL-only across the load context.
