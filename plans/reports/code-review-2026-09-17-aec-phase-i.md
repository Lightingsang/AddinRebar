## Score: 6 / 10

Sound where it was probed: the ledger is pure and its state machine pinned (ids, trim, caps, commit-once, revert, release); the replay table mirrors the shims exactly (same keys, same defaults, `changeSetId` forced null); the recorder validates the three handle keys up front and copies `args.Raw` so the request's document can go; the committer runs under one `SnapshotBag` that clones at `ObjectOpenedForModify` (before any change, skipping HANDSEED-new entities), unsubscribes on the way out and disposes on every exception path; clones are disposed on the main thread through a single idempotent `ReleaseSnapshots`; `DocumentToBeDestroyed` drops the ledger; rollback undoes in reverse dependency order, un-erases with `openErased`, `CopyFrom` keeps handles; the preview page (57.7 KB at 30 × 100 ten-char handles × 500-char args) and the 20-set summary sit under the cap; seeds are thin shims with every key read by literal; files ≤ 133 lines. Held back by three defects in the *life* of a set rather than in a single call: **a committed set can never be closed** — `IsLive` counts it against `MaxSets`, the only exit is `rollback`, so the 21st commit in a drawing session refuses every `begin_change_set` and up to 40 000 clones stay resident (H1); **rollback releases the undo state before it is known that the undo held** — a `dryRun` rollback (the description invites `dryRun` for commit) or a partial rollback on a locked layer marks the set `rolled_back`, disposes the snapshots, and the changes persist with no path back (H2); and **the verifier decides from the first non-empty class with a fingerprint blind to most `update` keys** — a real commit of a hatch-pattern / linetype / dimStyle / dynamic-state / XLINE set is reported *pending* on the next call, its snapshots dropped, and a re-commit double-applies any `move`/`rotate` in the set; the user deleting the created markup of a create + modify set does the same (H3). Plus a commit envelope of 111 KB at the op cap (M1), an uncapped rollback error path (M2), an atomic abort that counts against `commit_change_set`'s stability (M3), xref ops that record but never undo (M4), recorder coverage and op validation (M5), the pointer key (M6).
