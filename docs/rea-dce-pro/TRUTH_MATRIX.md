## 12. Forensic Evidence & Technical Causes of Blockers

### 12.1 Obfuscation Mechanism Details (`Babel .NET`)
- **JIT Decryption Hook**: In `DCE Pro.dll`, `DCE Excel.dll`, and `DBimRevit.dll`, method bodies of internal classes are protected by dynamic JIT compilation hooks. At compile time, the CIL bodies are replaced with stubs returning `null` or `0.0`. During execution, Babel .NET intercepts the CLR JIT compiler (`getJit`, token `0x1C00000E`) and decrypts native opcodes directly in executable memory pages via Win32 `VirtualProtect` (`mprotect`).
- **Metadata Representation Budget**: In large CAD vertical assemblies (`ZwDCE Pro.dll`, `GcDCE Pro.dll`), metadata exceeds 67,108,864 bytes, causing REA 6.6.0 `inspect-managed-members` to enter `coverage.state: unavailable`.
- **Duplicate #GUID Stream**: In `DBimRevit.dll` and `DCE Pro.dll`, the metadata table contains out-of-bounds heap indexes and multiple Module/Assembly table rows designed to corrupt naïve decompilers.

### 12.2 Clean-Room Strategy
- All high-level inputs, outputs, UI parameters, prompt chains, and keywords are **100% decoded** from `AiAgent/DanhBa/*.json`, DWG templates, and Excel workbooks.
- All mathematical and geometric algorithms are **100% reconstructed** in pure C# based on Vietnamese national standards (TCVN 5574:2018, TCVN 10304:2025, TCVN 5575:2024, TCVN 2737:2023) and validated by 369 unit tests.
- All legacy hardware node-locking, remote authentication APIs (`DbimTaiKhoanApi`), and background watchdogs (`DceGuard`, `DceUpdate.exe`) are permanently omitted.
